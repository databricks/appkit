# Generate TypeScript Types from JSON Schema

**Date:** 2026-03-12
**Status:** Brainstorm

## What We're Building

Eliminate hand-maintained TypeScript interfaces (`ResourceFieldEntry`, `ResourceRequirement`, `PluginManifest`, etc.) that are currently duplicated across `packages/shared/src/plugin.ts` and `packages/appkit/src/registry/types.ts`. Instead, generate them from the single source of truth: `packages/shared/src/schemas/plugin-manifest.schema.json`.

### Problem

- `ResourceFieldEntry`, `ResourceRequirement`, and `PluginManifest` are manually defined in **two places** and must be kept in sync with the JSON schema
- When the schema changes (e.g., adding a new resource type or field), developers must update the schema AND both TypeScript files
- The existing `tools/generate-registry-types.ts` already generates `ResourceType` enum and permission types from the schema, but the interface types are still hand-written

### Goal

- **One change, one place**: modify `plugin-manifest.schema.json` and all TypeScript types update automatically
- Remove duplicated interface definitions from `shared/src/plugin.ts` and `appkit/src/registry/types.ts`

## Why This Approach

### Hybrid: `json-schema-to-typescript` + slimmed custom script

**Generated by library** (into `packages/shared`):
- `PluginManifest` interface
- `ResourceRequirement` interface (without `required` field for manifest context)
- `ResourceFieldEntry` interface
- Permission type unions (`SecretPermission`, `JobPermission`, etc.)
- `ResourceType` as a string union type

**Kept in custom script** (runtime values that a type generator can't produce):
- `ResourceType` **enum** (runtime value needed for lookups)
- `PERMISSION_HIERARCHY_BY_TYPE` constant
- `PERMISSIONS_BY_TYPE` constant

**Kept hand-written in `appkit/src/registry/types.ts`** (not derivable from schema):
- `ResourceEntry` (extends generated `ResourceRequirement` with `plugin`, `resolved`, `values`)
- `ValidationResult`
- `ConfigSchema` (re-export of `JSONSchema7`)

## Key Decisions

1. **Use `json-schema-to-typescript`** library for interface generation — well-established (4M+ weekly npm downloads), supports JSON Schema Draft 7, `$ref`, `allOf`, `if-then`
2. **Generated types live in `packages/shared`** — single source of truth, `appkit` imports from shared
3. **Runtime-only values stay in custom script** — `ResourceType` enum, permission hierarchy constants. The script gets slimmed down but doesn't go away
4. **`appkit`-specific types stay hand-written** — `ResourceEntry`, `ValidationResult` extend/use generated base types
5. **Build integration** — generation runs as a pre-build step (same as today), output is a `*.generated.ts` file committed to the repo

## Scope

### In scope
- Add `json-schema-to-typescript` as a devDependency
- Create/update generation script to produce interfaces in `packages/shared/src/schemas/plugin-manifest.generated.ts`
- Remove hand-written `ResourceFieldEntry`, `ResourceRequirement`, `PluginManifest` from `shared/src/plugin.ts`
- Update `appkit/src/registry/types.ts` to import generated types from shared instead of re-declaring them
- Slim down `tools/generate-registry-types.ts` to only emit runtime values
- Update all imports across the codebase

### Out of scope
- Changing the JSON schema itself
- Generating types for `template-plugins.schema.json`
- Adding runtime validation (Zod) from the schema

## Resolved Questions

1. **Naming alignment**: Rely on auto-naming from `$defs` keys — current schema keys already produce correct PascalCase names (e.g., `resourceFieldEntry` -> `ResourceFieldEntry`). No `title` properties needed.
2. **Omit pattern**: Keep `Omit<ResourceRequirement, "required">` in hand-written wrapper code. Generate the full `ResourceRequirement` from the schema, apply `Omit<>` where needed in the `PluginManifest` type definition.
